## 1. 结论摘要

`yj` 是一个以数据库表为队列、由后台线程持续消费的批量预警服务，不是面向前端的 REST 服务。源码中没有 `@Controller`、`@RestController` 或业务 `@RequestMapping`；业务入口只有定时拉取和内部扫描契约。应用仍引入 Spring Boot Web/Actuator，配置了 `/yj` Servlet 前缀，并尝试用 `management.server.context-path=/app` 设置管理路径；该属性是否适配项目实际 Spring Boot 版本需在运行态验证，因此框架管理端点不能视为已确认的业务接口。

主链路如下：

```mermaid
flowchart LR
    A[每30秒调度] --> B[按最大申报时间从金三拉取流程]
    B --> C[写入 YJ_SBXX_HZ 状态20]
    C --> D[4个常驻线程候选查询]
    D --> E[数据库乐观锁 + 企业级本机锁]
    E --> F[按申报业务选择扫描器]
    F --> G[读取预警/指标/白名单配置]
    G --> H[执行指标 SQL]
    H --> I[写 YJ_DATA_YJXX]
    I --> J[任务状态 OK 或 YJ]
    J --> K[审核助手/便捷退税查询展示]
```

关键事实：

- 定时器每 30 秒执行一次，使用 Redis 锁 `zt:yj:lock:YJ_TASK_LOCK`，有效期 15 分钟。
- 当前定时拉取 SQL 只获取生产免抵退税 `LCSXA081038001`、外贸免退税 `LCSXA081039001` 两类顶层、未作废、未取消流程；特殊业务通常依赖审核助手的手动触发入口入队。
- 扫描端默认 4 个固定线程，一次最多查询 100 个候选任务；任务状态 `20` 表示待扫描，完成后为 `OK` 或 `YJ`。
- 指标枚举定义 68 项；按当前调用路径静态可达的指标为 47 项。其余 21 项虽然有枚举、SQL 或遗留私有方法，但当前入口不可达、被注释或被恒假条件禁用。
- 结果主表是 `TL_ADMIN.YJ_DATA_YJXX`，队列表是 `TL_ADMIN.YJ_SBXX_HZ`。审核助手通过这两张表读取状态和预警明细。
- 资源配置中存在明文数据库/Redis凭据，Druid 监控 Servlet 又允许任意来源并开放重置；应按已泄露凭据处置并立即收敛管理面。

## 3. 对外及内部业务接口总览

### 3.1 HTTP 接口结论

业务 HTTP 接口数：**0**。

未发现控制器类或显式业务 URL。审核助手中的 `/shzs/sb/yjxx/*` 才是前端查看、触发和处理预警的 HTTP 门面；它直接读写本服务使用的任务/结果表，并不是调用 `yj` 的 HTTP API。

非业务 HTTP 面需要单独治理：源码显式注册了 Druid `StatViewServlet`（URL 映射 `/druid/*`），并由 Spring Boot 配置管理上下文 `/app`。Druid 的当前配置允许任意来源、使用源码内固定登录凭据且允许执行重置；Actuator 的具体子端点随运行时版本和配置变化。因此它们不计入业务接口数，但部署验收必须枚举实际端点并验证网络隔离、强认证和最小权限。

## 4. 输入、输出与状态模型

### 4.1 定时拉取输入 `FetchTaskVo`

金三查询返回的核心字段：

| 字段 | 含义 | 用途 |
|---|---|---|
| `djxh` | 金三登记序号 | 映射纳税人电子档案号 |
| `lcswsxDm` | 流程税务事项代码 | 映射申报业务代码并选择扫描器 |
| `ssq` | 所属期 | 任务去重、指标统计范围 |
| `sbpc` | 申报批次 | 空值按 1 处理 |
| `sbrq` | 查询中取 `qdsj` 并格式化 | 任务水位及申报时间 |
| `ckqygllbDm` | 出口企业管理类别 | 写入 `zzsbb` 字段供部分规则使用 |
| `lcslid` | 流程受理 ID | 贯穿全部指标查询 |

定时拉取条件为：流程事项仅生产/外贸正式核准流程；`zlclcslid=lcslid`；作废、取消标志均为 `N`；`qdsj >= 水位`。

### 4.2 扫描输入 `TaskVo`

`TaskVo` 是内部统一业务上下文，主要字段如下：

- 任务：`id`、`lcId`（实际为申报业务代码）、`lcslid`、`sbztDm`、`sbzlDm`、`sbcs`、`sbpc`、`sbym`、`sbsj`。
- 企业：`nsrdzdah`、`nsrdjno`（纳税人识别号）、`cpcode/qyhgdm`、`swcode`、`qylxDm`。
- 申报报文：`sbbw`、`bwgs`、`bwqm`、`mwzy`、`bwzy`、`fileSize`。
- 运行状态：`tqbz/tqsj/tqcs`、`haveYjxx`、`tbpc`、`yjType`、`yjzbClosedTemp`。

### 4.3 预警输出 `YJ_DATA_YJXX`

每条命中记录的主要输出字段：

| 字段 | 含义 |
|---|---|
| `ID` | 当前实现为“5 位指标代码 + 本次该指标内序号”拼接值 |
| `TBPC` | 对外同步批次；不推送、白名单或关闭时为 0 |
| `SBID/NSRDZDAH/SBYM` | 任务、企业与所属期定位信息 |
| `YJCODE/ZBCODE` | 预警大类代码、具体指标代码 |
| `YJ_OBJECT/YJ_RECORD` | 预警对象与关联业务记录，如商品、供货商、报关单、申报序号 |
| `YJ_COUNT/YJ_AMT/YJ_TAX` | 命中数量、金额、税额 |
| `YJ_MSG/SCORE` | 面向审核人员的预警文本和指标得分 |
| `CL_FLAG/CL_DATE/CL_USER/CL_MSG` | 后续处理状态、时间、人员和意见 |
| `QYFLAG/SWFLAG/BMDFLAG` | 企业端/税务端适用标志及白名单/关闭标志；`BMDFLAG=0/1/2` 分别为正常、白名单、关闭 |

### 4.4 任务状态与锁

| 状态/字段 | 含义 |
|---|---|
| `SBZT_DM=20` | 待扫描，可进入候选队列 |
| `SBZT_DM=OK` | 扫描完成，未发现任何原始命中 |
| `SBZT_DM=YJ` | 扫描完成，至少一个指标返回过命中；不保证存在可同步记录，审核助手的机关级展示开关还可能隐藏整批结果 |
| `TQBZ` | 数据库锁令牌；为空表示未锁定 |
| `TQSJ` | 最近锁定时间；超过 5 分钟可重试 |
| `TQCS` | 锁定/重试次数；SQL 仅选择 `<10` 的任务 |

锁定过程使用数据库条件更新保证跨实例竞争安全，并额外用 `Cache` 键 `yj_<nsrdzdah>` 防止同一企业并发。`tokenMode` 默认是 `local`，此时它只是 JVM 内缓存、不是分布式锁；若部署配置改为 `redis` 才会共享。默认模式下的跨实例约束仍取决于数据库 SQL。

## 8. 与 shzs 审核助手的协作边界

审核助手不通过 HTTP 调用本服务，而是共享数据库/Redis 约定：

1. `/shzs/sb/yjxx/excute` 根据 `lcslid` 查询或插入 `TL_ADMIN.YJ_SBXX_HZ`；新任务将 `SBCS=999` 作为人工优先标志，已有任务会重置扫描次数和提取标志。
2. `yj` 消费状态 `20` 的任务，写 `YJ_DATA_YJXX` 并把状态改为 `OK/YJ`。
3. `/shzs/sb/yjxx/view` 轮询任务状态并查询预警明细；`/update/clmsg` 回写处理意见。
4. 便捷退税/同步程序以 `TBPC`、`QYFLAG/SWFLAG/BMDFLAG` 判断可同步或可展示记录。

这是一套数据库级协议，字段状态和值的变化即接口契约；修改任务状态、锁字段、`TBPC` 或白名单含义必须同时验证两个服务和下游同步程序。

## 9. 重要问题与改进建议

### 9.1 高优先级

1. **仓库包含明文基础设施凭据。** `application-pro.properties`、测试/开发配置和 `generatorConfig.xml` 中存在数据库或 Redis 口令，Druid 登录凭据也硬编码在 Java 中。不能只删除当前文件：应先轮换所有可能受影响的凭据，改用密钥管理/部署注入，限制最小权限，再按组织流程清理 Git 历史并启用提交前秘密扫描；本文不复述具体凭据值。
2. **Druid 管理面配置危险。** `DruidConfig` 无环境限定，允许任意来源访问，开启重置能力；同时应用关闭管理安全。应默认不注册，必要时仅绑定管理网、强认证、关闭 reset，并在网关/防火墙层拒绝业务网和公网访问。
3. **单条增量可能长期不入队。** 水位查询用最大 `sbrq`，来源查询用 `qdsj >= 水位`，随后只要结果集大小恰好为 1 就直接返回。若水位之后确实只有一条新流程，它会被误当成上次边界重复项，直到出现第二条才可能被处理。应使用稳定复合水位（时间 + 主键/流程 ID）并以唯一键幂等插入，不应以结果条数判断重复。
4. **任务大小分流条件失效。** Java 给 `less` 赋值 `"1"/"0"`，`YsMapper.xml` 却判断 `less == 3/4`，因此大/小报文过滤永远不会生效，四类线程实际竞争同一候选集。
5. **排序表达式被当参数绑定。** `ORDER BY #{orderByCaluse}` 不能按预期生成 `sbcs desc,sbrq asc` 的 SQL 标识符排序，可能成为常量排序或触发数据库错误。应将允许的排序方案固化为 `<choose>` 白名单。
6. **失败任务无明确失败态。** 扫描异常后不更新状态，只等待锁超时重试；`TQCS` 达到 10 后任务仍是 `20`，但永远不再被选中。建议增加 `FAILED/DEAD` 状态、错误码/错误摘要、最后失败时间和人工重放接口。
7. **预警明细 ID 有并发冲突风险。** `ID` 只由 `zbcode + 本指标内序号` 组成，未包含任务 ID 或数据库序列。若数据库对 `ID` 有全局唯一约束，不同任务同时命中同一指标会冲突；需查库确认约束并改用序列/UUID。

### 9.2 一致性与可观测性

1. 重扫的“删除旧结果 → 多次指标查询/插入 → 更新任务状态”没有一个清晰的整体事务，且跨多个数据源，任一步失败可能留下部分结果或旧结果已删但状态未完成。建议用任务版本/临时批次写入后原子切换，或建立可恢复的 Saga 状态。
2. `haveYjxx` 在取得首个原始命中、申请 `TBPC` 时即设为 `true`；即使所有结果随后因白名单或开关变成 `TBPC=0/BMDFLAG=1/2`，任务仍会标为 `YJ`。审核助手当前查询又没有按 `BMDFLAG/SWFLAG` 过滤，因此被白名单抑制或关闭同步的记录仍可能展示给审核人员。应明确区分“原始命中”“可同步”“税务端可见”“企业端可见”，并由统一契约控制过滤。
3. 重扫删除条件不是只按当前 `sbid`，而是删除同企业、同业务、同所属期、同批次对应的所有任务结果。若同一业务键允许多条任务，需要确认这是预期覆盖还是误删风险。
4. 任务候选查询到完整记录失败时，代码在判空前调用 `ysxx.set...`，会抛空指针并让任务等超时重试；应先判空并记录结构化失败原因。
5. 定时器只自动发现生产/外贸两类正式流程，而工厂支持更多业务。建议将“可发现业务”和“可扫描业务”配置统一，监控各业务的来源数量、入队数量、完成数量和滞留数量。
6. 定时拉取锁使用固定 15 分钟租约且没有续租；若一次拉取/入队超过租约，另一实例可再次进入。应按最大执行时长设计自动续租，或让入队操作具备数据库唯一键保护。

### 9.3 配置与代码治理

1. 当前 21 个枚举指标不可达，其中多个仍保留完整 SQL/私有实现。应由业务确认“已下线”还是“漏接入口”，确认后删除死代码或恢复调用，并建立 68 项配置—入口—SQL—输出的自动一致性测试。
2. `YJ_DIC_CODE` 和 `YJ_DIC_YJZB` 的缺失配置可能导致取分值或适用标志时空指针；建议启动时做配置完整性校验并拒绝带缺口启动。
3. 管理端安全被显式关闭。即使该服务没有业务 Controller，也应只绑定管理网、设置独立管理端口并开启认证/最小暴露。
4. 全局旁路 `isClosedYjBreak=false` 会绕过大类和指标开关；16405 的布尔表达式还会同时绕过外贸业务限定。生产环境应禁止动态打开旁路，并把业务限定放到无法被旁路覆盖的外层条件。
5. 建议补充指标级监控：扫描次数、命中数、抑制数、耗时、SQL 异常、失败重试、队列龄期，以及按 `lcslid/sbid/zbcode/tbpc` 的可追踪日志。

## 10. 建议的验收用例

- 增量边界：同一秒 1 条、2 条、多条；相同 `qdsj` 不同 `lcslid`；任务重复拉取的幂等性。
- 并发：同企业多个批次、不同企业同指标、两个服务实例、Redis 锁过期后重入。
- 重试：指标 SQL 异常、配置缺失、结果主键冲突、跨数据源超时，验证第 10 次后的可运维状态。
- 白名单/开关：整体白名单、对象白名单、大类关闭、指标关闭、企业端/税务端适用组合，分别核对任务状态与可见结果。
- 业务覆盖：生产、外贸各 47 项可达集合；外综服/已用设备/非自产消费税目前仅 11601、11801 的预期确认。
- 两服务联调：审核助手手工触发、状态轮询、Excel 导出、处理意见回写，以及便捷退税同步对 `TBPC/BMDFLAG` 的解释。
- 安全：秘密扫描不再检出有效凭据，旧凭据均已轮换；从业务网访问 `/druid/*`、`/app/*` 应失败，管理网也只能以最小权限账户访问且不能执行 Druid reset。
